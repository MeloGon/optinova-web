# Transform #5: ID automático de `pacientes`

Los IDs que ya existen **no cambian**: se importan tal cual desde PROD. La migración `20261026190000_pacientes_id_automatico.sql` solo agrega la secuencia que asigna los IDs de los pacientes nuevos y la coloca en `max("ID PACIENTE") + 1` según los datos que haya al aplicarla.

## Orden en el corte (Fase 5)

1. Restaurar los datos de PROD en `optinova-db` (esquema viejo).
2. Aplicar las migraciones en orden. La #5 recoloca la secuencia sobre los datos importados.
3. Si se importaran más filas **después** de aplicarla (por ejemplo, un segundo pase de datos), volver a ejecutar:

```sql
select setval('public.pacientes_id_seq', (select coalesce(max("ID PACIENTE"), 0) + 1 from public.pacientes), false);
```

## Verificación del ensayo de corte

```sql
-- El siguiente ID debe ser mayor que todos los existentes.
select (select max("ID PACIENTE") from public.pacientes) as mayor_id,
       (select last_value from public.pacientes_id_seq) as siguiente_id;
```

`siguiente_id` debe ser igual a `mayor_id + 1`.

## Nota para la app

En PROD hay 112 pacientes con ID mayor que 9,007,199,254,740,991 (el límite exacto de un número en JavaScript). La app los lee y envía como **texto** (`"ID PACIENTE"::text`); nunca debe convertirlos a número.
